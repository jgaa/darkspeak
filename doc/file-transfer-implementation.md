Both production directions use session roots; the old execution controllers have been removed. The focused owner, authenticated paired, journal and restart regressions pass. Production advertisement is enabled; application build and private-Tor execution remain at the release gate. The table below records the original owners and their migration destinations.

The manager belongs in core under the existing application engine lifetime and uses `PeerConnection` for transport, shared by feature controllers. Its active registry uses authenticated local/remote scope, transfer ID and direction (`dsfm::TransferKey`); delivery additionally checks the current connection and attempt. No new attempt overlaps outstanding I/O or publication from the previous session. Transfer identity stays stable across attempts; completed EOF replay verifies committed content without another partial writer or publication.

One retained root `QCoro::Task` per session expresses admission/authorization, preparation, negotiation, bounded payload/checkpoint exchange, full-file verification, receiver publication and finalization. Child operations are awaited or joined; the manager joins roots on shutdown. Only the root writes execution phases/outcomes and issues durable lifecycle commands. File states and transport tables cannot act as competing phase machines.

Wire events comprise decisions/readiness, resume selection, chunks, flow ACKs, checkpoint phases and typed pause/cancel. Local commands cover disconnect, deadline, source/policy change and user actions. Peer validates hostile input before routing; the session checks phase-dependent meaning before work. Chunk delivery retains the eight-chunk and byte bounds; control/command delivery also has fixed local bounds and coalesces valid duplicates/wakeups. Exhaustion stops admission and wakes the owner for safe interruption, never spawning unbounded tasks. Awaitable notification replaces the `preparing_initial_offer` 25 ms polling loop and independently launched pump/drain/confirmation work. Existing fair bulk scheduling and control priority remain transport services.

The journal API is sufficient without a schema change: `create/load`, `selectResume`, `validateAttempt`, transactional `beginAttempt`, `record`, `pause`, `fail`, `complete`. Preserve the version-three journal and fixtures. The journal is authoritative; application history is derived. Freeze metadata/interval/nonce before payload, verify sender source and receiver durable prefixes before readiness, retain separate flow/checkpoint windows, and require final full-file verification and mutual final checkpoint confirmation with the existing final-flow/completion ordering.

Cancellation ordering: synchronously close admission/write/publication eligibility, signal the owner, stop new work, cancel cancellable operations, join outstanding work, settle durable evidence, release resources, and project one outcome. Preserve storage's atomic commit boundary: explicit cancellation before irreversible publication prevents publication; committed publication wins a racing cancellation. Disconnect retires transport but allows fully received local verification/publication to finish, with its cancellation distinct from transport retirement under the same owner. Disconnect retains resumable partials; explicit cancel aborts unpublished partials; typed pause/failure remain distinct. The two-per-contact reservation and `ManagedStorage::holdOperation()` stay held until real I/O and cleanup return, replacing `FileTransferWork` handoffs and weak-reference slot accounting.
